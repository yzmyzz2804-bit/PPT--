# 验收、测试和升级

## 三层验收
1. 包内静态检查：所有JSON可解析；示例/模板符合Schema；配置引用的prompt和schema存在。
2. 门控单元测试：合法推进、非法跨步、审批缺失/目标变更/凭据变化/范围错误、关键待核事实、输入文件变动、QA未检查、跨版缺失、渲染文件变化、重复初始化与路径逃逸。
3. TRAE端真实验收：用一份已知页数与指标的PPT跑通，逐页检查实际渲染；无图页不强塞图；打印实际纸面复核；保护图片逐对象比较。

第1/2层通过不等于第3层通过；本包不包含用户实际PPT与TRAE本机渲染结果。
自动化检查不理解图片语义和事实真假，claims/QA内容须由核验角色真实执行，必要时人工复核。

## 必须覆盖的业务测试
- 纪要内有看似合理的错误数据：必须进入未核清单，不能以Architect OS已完成为证据。
- 扫描PPT仅OCR了一半：禁止推进到内容方案，报告缺页。
- 用户说优化一下：只能提案，不能重排既有文本/替换图片/重做已确认分析。
- 获准调第3页图片但尝试改第5页分析：拒绝，scope不匹配。
- 批准后更改标题/数据/渲染文件：旧审批不得继续放行。
- 同一事实在两个版本值不同：QA失败，不以版式差异解释。
- 参考网站打不开或内容过期：记录失败，关键论据暂停，不捏造网页支持。
- 同一问题重试3次仍失败：BLOCKED，提供问题与恢复点。
- 会议纪要没有明确来源：可以归档，不可以自动标为已核事实。

## 升级链
feedback → change proposal → 人工批准范围 → 新config/prompt/skill版本 → 单元回归 → 新真实样本验收。
未获批准，auto_apply必须为false。修复历史业务产物在新运行ID或新版本副本进行，发布清单与原件不就地改写。
