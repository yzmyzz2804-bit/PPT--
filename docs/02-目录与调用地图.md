# 文件分层与 Agent 调用地图

```text
工作台根目录/
  integration/PROJECT_RULES.md   # 一级规则：唯一短常驻规则
  .trae/skills/                 # 能力方法：按需加载，不包含业务资料
  config/                      # 项目默认值：主控读取所需部分
  schemas/                     # 机器契约：输入输出校验
  prompts/                     # 角色步骤：每阶段只读对应提示词
  templates/                   # 产物形状：按需复制到当前运行
  scripts/ tests/              # 门控与验证，不含PPT生成器
  reference/                   # 原稿与v5：只溯源，不自动加载
  runs/RUN-001/
    task.json capabilities.json state.json handoff.md
    00_inputs/                 # 上传原件，文件哈希锁定，不回写
    01_memory/                 # 识别、短索引、约束草案与确认版本
    02_evidence/               # 来源快照、事实/派生指标与核验结果
    03_content/                # 2–3方案、选定方案、共同内容模型与页框架
    04_render/                 # 汇报与打印版的独立渲染副本
    05_qa/                     # 检查证据、问题、待发布清单
    06_release/                # 经过审批的发布清单与交付快照
    07_feedback/               # 运行反馈和升级提案
    approvals/                 # 人工授权记录及原始确认凭据
    audit/                     # 事件日志；仅应用层追加，不防恶意篡改
```

准确读写列表以 `config/agents.json` 为准。目录路径相对运行根目录；`config/`、`prompts/`等相对工作台根目录。
受保护资产可细到页、形状、段落、图表：如PPT第3页shape:chart-2；不要把一个大PPT的“允许调整”误认为所有对象都可改。

## 每个角色的加载顺序
主控：短规则 → state → 当前索引 → workflow → 该角色prompt。
识别：任务与原始文件 → 标签与可读性报告；不做数据正确性担保。
约束：识别摘要与目标 → constraints 草案；默认不需要为起草而打断用户。
核验：保护范围、相关原页/纪要、来源登记 → claims；检索加载优选站技能。
策划：核验通过的claims与批准约束 → 方案 → 选定 → 页框架 → 物料；不能调用渲染器先做成品再补审批。
渲染：已批准deck + 已批准的layout profile → 两套输出；不能根据美观自行改数值。
QA：源ledger + deck + 渲染实际文件 → 质检报告；不只看策划摘要。
归档：匹配审批的待发布清单 → 正式交付 → 反馈提案。

## 二级记忆不等于缓存所有内容
摘要用于导航，原始页和核验证据用于结论。索引包括哈希与版本；内容变更即失效旧索引。
交接只传输出路径/哈希/摘要/问题/下一状态，遵守 `schemas/envelope.schema.json`。
恢复会话先查 state.json、handoff.md、关键产物哈希，再继续；不要把所有历史对话重新读入。

补充：每个运行根目录还包括config_lock.json。源配置位于根目录config，锁文件保存这些文件的冻结哈希，不是自动复制所有项目历史。
config/prompt_bundle.json 是提示词JSON总入口；主控按id选取，不能把8段一次全部注入。
