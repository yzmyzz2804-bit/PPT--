# 对象级排版门控 · v7

# AI-PPT工作台规则 v7.2.0

## 不变的边界
原件只读；Architect OS仅提供纪要内容；业务数据、文字语义、图像本体与既有分析的保护不因版式优化取消。
项目默认汇报16:9，打印A3横向420×297mm。版式派生可改字号、边距、换行和分页，不得擅自改数值、单位、楼号、高度、正文含义或图纸标注。
短规则常驻，源材料按对象和标签按需读取；不宣称文件落盘能释放当前会话已有上下文。

## 004几何切块失败复盘
33页按最小字号放大后被拆成132页。自动字号检查132页通过，字符包围盒32/33源页通过，但实际视觉发现表格/图纸/大标题被割裂。
根因：把坐标区域误当语义对象；没有保持表头—主键—行列关系；没有保护完整图块；只检查局部字号，没有检查对象完整性和跨页阅读关系。
这不是通过降低字号或增加重叠边缘就能解决的bug。禁止把“字号通过”“像素未丢”当作对象级重排通过。

## 对象级重排
1. 先识别并登记源对象，再布局。每对象有source_page、bbox、源哈希、类型和输出页映射。
2. 正文按段落和行流动，标题完整，与后续段落保持关联；不在字形中线机械切页。
3. 表格必须有原单元格矩阵。按行分页重复表头，按列分页重复主键；不改源单元格，不猜未解析内容。
4. 图纸、照片、分析图保持完整。局部放大是辅助，不替代整图；无法识别边界则保留整页参考并标未完成，不能记为重排成功。
5. 图内嵌小字需要独立可读性检查。对象完整与字体达标分别验收，任一失败都不得判最终通过。
6. 未恢复的表、图、段落有明确未完成状态。仅字符框覆盖或无空白不能证明内容关系正确。

## 新版门控
以config/object_layout_gates.json和docs/09-对象级排版门控.md为准。L01—L09分别覆盖识别、段落、表格解析、表格分页、图纸、可读性、覆盖、视觉及测试隔离。
scripts/check_object_layout.py是对象清单的结构及一致性辅助检查；它不替代源PDF解析、实际字体测量、图像相等或人工审批。
生产渲染门要求03_content/object_layout.json通过。测试分支可以输出失败样本，但必须记录实际失败且不得发布。

## 工程自修复与报告
确定可复现的工程bug可在独立版本修复并回归；禁止自批授权、把unverified改verified、删除QA或降低阈值。
报告按阶段、阻塞变化、修复回归和最终结论汇总；重复问题合并。原始事件与逐页明细保留。
新版本运行新建配置锁；v6旧运行和审批不就地改写，不自动继承。

## 校验脚本说明
`python scripts/check_object_layout.py --manifest <当前运行>/03_content/object_layout.json`
输入契约为schemas/object_layout.schema.json。脚本检查源页覆盖、对象映射、正文规范化一致、表格行列/主键重复及逐格一致、图对象不切割标志、字号、状态和visual引用。
必须由渲染器记录真实测量数据和证据，不能仅填写pass布尔值。脚本仍无法独立判断上游填入证据是否真实，也不能认证图片像素相等；需要原图对照与视觉QA。
失败退出码2；输出fail/unknown即不可推进生产RENDERED门。参考页不能当作已完成重排对象。
生产流程将该清单绑定deck SHA，并重新核对源input SHA、输出文件SHA及实际PDF页数；正式验收仍受既有审批与QA限制。
旧v6运行没有该清单，不可直接在v7上重锁冒充通过；迁移到新运行重新检查。
