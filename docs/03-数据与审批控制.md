# 数据核验与人工审批

## 事实账本
每条重要数字/结论分配 claim_id，保留原文、页码/表格/单元格、值、单位、期间、分母、来源、核验方法。
派生指标必须有 formula 与 inputs；仅“数字抄对”不等于统计口径正确；趋势判断也要核对基期、样本和范围。
事实、推断、建议分别标记。建议不是待核事实，但如果建议依赖数据，该数据仍须核验。
关键事实处于 unverified/conflict 时阻止发布；一般背景待核信息不能作为关键论据，若保留必须明确标注且经内容审批。
用户原件中发现错误，不改原件、不静默改结论：记录原值/建议值/计算依据/影响页，申请 data_correction。
引用标准必须记录发布机关、版本、适用时间；旧版在历史案例中可能适用，不把“最新”机械等于“适用”。

## 审批对象
- contract：`01_memory/constraints.json`，保护范围、改动目标、版式模式与输入文件关系。
- option：`03_content/selection.json`，绑定 options_sha256，防方案变了还沿用选择。
- content：`03_content/deck.json`，整册大纲、逐页框架、引用与保护变更。
- protected_change：具体差异提案 JSON，必须包含保护对象、before_sha256、after_sha256、范围和理由；scope须与deck引用一致。
- release：`05_qa/release_manifest.json`，绑定实际成品哈希、QA和deck，不是批准一个文件名。

使用 `templates/approval.json` 建立记录。人工明确确认的原始消息或签批文件单独保存在 approvals/，计算证据哈希。
不得让模型自己写“用户已同意”来代替凭据。本包只能核验凭据文件与记录一致，不能独立认证操作者身份。
宿主应把记录审批的工具与修改规则的工具从执行 Agent 权限中移除，或要求人在UI确认后由受控桥接器写入。

## 变更与失效
审批不匹配运行ID、目标路径、目标SHA、范围、撤销状态或证据SHA，门控拒绝。
约束/数据/内容/渲染任何上游改变，下游通过链接哈希检查失效；重新核验并重新审批。
不依赖记录日期推断权限，撤销用revoked=true并保留原记录；不要删除历史审批。
有新修改时在新副本/新运行ID继续。禁止覆写00_inputs；发布版本不可就地修改。

## 问题分级与回退
P0：保密泄漏、无权限结构/图片/分析改动、关键数字冲突、原件哈希变动。立即停止发布，保留证据与原件。
P1：缺页、未核引用、跨版结论不一致、严重溢出。只回退到证据/内容/渲染中受影响的阶段。
P2：非保护对象的轻微对齐/格式问题，可在批准范围内修复并重新QA。
BLOCKED 记录 resume_state，原因记录到审计事件；resume重新检查输入、冻结配置和恢复点依赖。rollback保守归档全部阶段产物并令全部审批失效，保留业务文件，不自动修订业务内容。旧版运行仅通过migrate新建运行基线，不允许原地重锁或继承旧审批。

## 配置冻结
初始化时记录config_lock.json。约束的config_lock_sha256绑定该文件，人工批准约束即批准该配置基线。
版式、提示词、门控、Schema或技能发生变化，当前运行的链条检查会拒绝继续；先形成升级提案，再新建运行或明确归档失效产物与重新审批。
网页证据必须保存正文摘录快照及snapshot_path，SHA校验快照而不是URL字符串；合理保留相关内容，不批量复制版权资料。
